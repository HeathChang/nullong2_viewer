# 폴더째 읽는 뷰어 — 기획

> 기획안 v0.2 · 백엔드 0 · 정적 웹 · 범위 확정

로컬에 흩어진 마크다운·JSON·텍스트를, 업로드 없이 폴더 단위로 열어 오가며 읽는다.

| | |
| --- | --- |
| **한 번 열면 끝** | 폴더 하나를 승인하면 그 안의 모든 문서를 클릭 한 번으로 오간다 |
| **기기 밖으로 안 나감** | 업로드도 서버도 없다. 브라우저가 디스크에서 직접 읽고, 고친 내용도 제자리에 쓴다 |
| **오래 읽어도 편하게** | 한국어를 포함해 어떤 언어의 문서든 깨지지 않고 읽히도록 |

## 1. 지금은 왜 불편한가

로컬에 `.md`·`.json` 파일이 쌓이는 상황은 흔하다. 레포의 `docs/`, API 응답 덤프,
LLM이 뱉어낸 리포트 묶음, 내려받은 데이터. 그런데 이걸 그냥 *읽기만* 하려는 순간
선택지가 전부 어긋난다.

- **에디터를 켠다** — VS Code를 띄우고, 미리보기 패널을 열고, JSON은 포매터를 돌린다. 읽기 하나에 과한 절차다.
- **브라우저로 연다** — 마크다운은 원문 그대로 나오고, JSON은 한 줄로 뭉개진다. 폴더 안 다른 문서로 넘어가려면 주소를 다시 친다.
- **온라인 뷰어에 붙여넣는다** — 사내 문서나 개인 데이터를 남의 서버에 올리는 일이 된다. 한 번에 한 파일뿐이다.

빠진 것은 렌더링 품질이 아니라 **탐색**이다. 문서는 대개 혼자 오지 않고 폴더로 온다.

## 2. 누가, 어떤 순간에

| 사용자 | 순간 | 성공의 모습 |
| --- | --- | --- |
| 개발자 | 처음 보는 레포의 `docs/`를 훑는다 | 폴더 열고 30초 안에 문서 구조가 파악된다 |
| API 작업자 | 응답 덤프 `.json` 수십 개를 비교한다 | 트리로 접었다 펴며 키 경로를 바로 복사한다 |
| AI 사용자 | 에이전트가 만든 리포트 묶음을 검토한다 | 목차 따라 읽고, 문서 간 링크를 눌러 이동한다 |
| 기획·데이터 | 받은 데이터 파일이 뭔지 확인한다 | 업로드 없이 열어 훑고, 필요한 값만 집어낸다 |

넷 모두 **쓰기가 아니라 읽기**이고, **한 파일이 아니라 폴더**다.

## 3. 정적 웹으로 간다

"웹이냐 크롬 확장이냐"가 첫 갈림길이었다. 결론은 **정적 웹**이다.
확장이 로컬 폴더를 더 잘 읽어줄 거라는 기대가 사실이 아니기 때문이다.

| | 정적 웹 | 크롬 확장 |
| --- | --- | --- |
| 폴더 통째 탐색 | 가능 — `showDirectoryPicker()` | 같은 API를 써야 함. 더 나은 점 없음 |
| `file://` 디렉토리 나열 | 불가 | 사실상 불가 — 크롬의 목록 HTML을 파싱해야 하고, 사용자가 권한 토글까지 켜야 한다 |
| 설치 | 불필요, URL만 | 스토어 심사 · 설치 필요 |
| 배포·업데이트 | 푸시하면 끝 | 심사 대기 |
| Firefox · Safari | 폴백 동작 | 별도 확장을 새로 만들어야 함 |
| OS에서 파일 더블클릭 | PWA 설치 시 가능 | 불가 |

**전제 조건** — 보안 컨텍스트(HTTPS 또는 `localhost`)에서만 동작한다.
`index.html`을 더블클릭해 `file://`로 여는 방식으로는 안 된다.

**한계와 폴백** — 이 API는 Chromium 계열 전용이다. Firefox와 Safari에는
`<input webkitdirectory>`와 폴더 드래그앤드롭으로 **스냅샷 모드**를 제공한다.
읽기는 똑같이 되지만 제자리 저장·변경 자동 감지·재방문 복원이 없다. 배지로 명시한다.

## 4. 무엇을 열 수 있나

### Tier 0 — 제품의 정체성 (M1–M2)

`.md` `.markdown` `.mdx` `.json` `.jsonc` `.jsonl` `.ndjson` `.yaml` `.yml` `.txt` `.log`

- **마크다운** — GFM 표·체크박스·각주, 코드 하이라이트, Mermaid, KaTeX, 상대경로 이미지, 문서 간 링크 이동
- **JSON** — 접이식 트리, 키/값 검색(접힌 노드까지 찾아 자동 전개), 경로 복사, 원문/트리 전환, 주석·후행 쉼표 관용 파싱
- **YAML** — JSON과 같은 트리 뷰
- **JSONL** — 줄 단위 레코드, 깨진 줄은 표시하되 나머지는 정상 렌더
- **텍스트·로그** — 줄 번호, 줄바꿈 토글, 긴 파일 점진 로드
- **편집·저장** — 기본은 읽기 모드, 편집은 명시적으로 켠다

### Tier 1 — 같은 폴더에 늘 함께 있는 것 (M3)

`.csv` `.tsv` `.toml` `.ini` `.env` `.xml` 소스 코드 이미지

이미지가 필요한 진짜 이유는 **마크다운 안의 상대경로 이미지**다. 없으면 문서에 구멍이 뚫린다.

### Tier 2 — 있으면 좋은 것 (M4 이후)

`.ipynb` `.pdf` `.html` `.svg` `.parquet` — 전부 지연 로드.

### 범위 밖

파일 변환, 압축 해제, DB 파일, 여러 파일 일괄 치환.
편집은 "보다가 한 줄 고친다" 수준까지이고, 에디터를 대체하려 하지 않는다.

## 5. 화면은 세 칸

```
┌─────────────────────────────────────────────────────────┐
│ ☰  my-project / docs / guide.md      ⌘K   Aa   ◐        │
├──────────────┬──────────────────────────┬───────────────┤
│ 파일          │                          │ 목차           │
│ 🔍 거르기      │      본문                 │ 시작하기        │
│ ▾ docs       │                          │   설치         │
│   guide.md   │                          │   설정         │
│   api.md     │                          │ API           │
│ ▾ data       │                          │   인증         │
│   users.json │                          │               │
└──────────────┴──────────────────────────┴───────────────┘
```

좁은 화면에서는 트리가 서랍으로, 목차는 상단 드롭다운으로 접힌다.
아무 폴더도 열지 않은 상태가 사실상 랜딩 페이지다 — 드롭 영역, 폴더 열기,
최근 연 폴더, 그리고 "파일은 이 브라우저를 벗어나지 않습니다" 한 줄.

## 6. 읽는 동안의 손놀림

목표는 세 가지 수치다. 폴더 열고 첫 문서까지 **2클릭**, 다른 문서로 전환 **1동작**,
재방문 후 복귀 **1클릭**.

### 탐색
- **빠른 찾기** — 파일명과 경로를 함께 퍼지 매칭
- **문서 안 링크** — 상대경로 마크다운 링크는 앱 안 이동, 외부 링크만 새 탭
- **앞으로·뒤로** — 문서 이동 기록
- **이어 읽기** — 파일마다 스크롤 위치 기억

### 검색
- **문서 안 찾기** — JSON은 *접힌 노드까지 뒤져서 자동으로 펼친다*
- **폴더 전체 검색** — 웹 워커로 모든 파일 내용을 훑는다. 이 기능이 "뷰어"를 "문서함"으로 만든다

### 편집
기본은 읽기다. 그래서 편집을 *모드*로 분리한다. `⌘E`로 켜기 전에는 파일이 바뀌지 않는다.

- **명시적 저장** — `⌘S`로만 디스크에 쓴다. 자동 저장은 없다
- **충돌 방지** — 저장 직전에 디스크의 수정 시각을 다시 읽는다. 내가 연 뒤에 바뀌었으면 덮어쓰지 않는다
- **형식 검사** — JSON·YAML은 저장 전에 파싱해 본다
- **에디터는 필요할 때만** — 편집 모드에 들어가는 순간 동적으로 불러온다
- **폴백 모드** — 스냅샷 모드에서는 제자리 저장이 불가능하다. 내려받기로 대체한다

### 단축키

| 키 | 동작 |
| --- | --- |
| `⌘K` | 파일 빠른 찾기 |
| `⌘F` | 문서 안에서 찾기 |
| `⌘⇧F` | 폴더 전체 내용 검색 |
| `↑` `↓` | 트리에서 파일 이동 |
| `⌥←` `⌥→` | 이전 · 다음 문서 |
| `⌘B` | 사이드바 접기 · 펴기 |
| `⌘E` | 편집 모드 |
| `⌘S` | 저장 |
| `⌘+` `⌘−` | 글자 크기 |
| `R` | 현재 문서 다시 읽기 |
| `?` | 단축키 도움말 |

## 7. 어떤 언어로 쓰인 문서든

"다양한 언어"는 두 개의 다른 문제다. 섞으면 둘 다 어설퍼진다.

**UI 언어** — `navigator.language`로 자동 선택하고 수동 전환. 한국어·영어로 시작한다.

**문서 언어** — 이쪽이 진짜 난이도다. 내가 만든 문서가 아니므로 무엇이 들어올지 모른다.

- **인코딩 추론** — BOM을 먼저 보고, UTF-8 엄격 디코딩을 시도한 뒤, 실패하면 CP949·Shift_JIS·GB18030·Big5를 돌려가며 *가장 덜 깨지는* 결과를 고른다. 결과는 상태 표시줄에 밝힌다
- **줄바꿈** — 한국어는 `word-break: keep-all`로 어절 단위로 끊어야 읽힌다. 긴 URL·코드는 따로 처리한다
- **글꼴 폴백** — 문서 언어를 추정해 `lang` 속성을 붙이고 언어별 폴백 스택을 태운다. 네트워크 없이 동작해야 하므로 시스템 글꼴 기반
- **RTL** — 아랍어·히브리어가 감지되면 `dir="rtl"`
- **숫자·날짜** — `Intl`로 현지 형식

## 8. 성능 예산

| 항목 | 예산 | 방법 |
| --- | --- | --- |
| 초기 JS | ≤ 180 KB | gzip 기준. 편집기·Mermaid·KaTeX 제외 |
| 폴더 스캔 | ≤ 3 s | 파일 1만 개. `node_modules`·`.git` 등은 건너뛴다 |
| 문서 첫 표시 | ≤ 120 ms | 1 MB 마크다운 |
| JSON 트리 스크롤 | 60 fps | 10 MB 파일. 펼쳐진 노드만 그린다 |
| 전체 검색 | ≤ 2 s | 1천 개 파일. 웹 워커 |

## 9. 기술 스택

| 층 | 선택 | 이유 |
| --- | --- | --- |
| 빌드 · 앱 | Vite + React + TypeScript | 정적 산출물만 나온다 |
| 마크다운 | marked + DOMPurify | 로컬 파일도 신뢰하지 않고 살균한다 |
| 코드 하이라이트 | highlight.js | 언어 팩을 필요한 만큼만 싣는다 |
| YAML | yaml | 트리 뷰는 JSON과 공유한다 |
| 다이어그램 · 수식 | Mermaid · KaTeX | 해당 블록이 있을 때만 동적 import |
| 편집기 | CodeMirror 6 | 편집 모드에 들어갈 때만 동적 import |
| 상태 · 저장 | zustand · IndexedDB | 폴더 핸들과 읽기 설정을 브라우저에 남긴다 |
| 무거운 작업 | Web Worker | 전체 검색, 대용량 JSON 파싱 |
| 배포 | 정적 호스팅 | 빌드 산출물을 그대로 올린다 |

## 10. 만드는 순서

각 단계가 끝나면 그 자체로 쓸 수 있는 상태여야 한다.

1. **M1 — 폴더를 열고 읽는다** ✅
   폴더 선택 · 재귀 스캔 · 트리 사이드바 · 마크다운 렌더 · JSON·YAML 트리 ·
   텍스트 뷰 · 라이트/다크 · 빠른 찾기
   *완료 기준 — 내 `docs/` 폴더를 열어 VS Code 없이 끝까지 읽을 수 있다*

2. **M2 — 오래 읽어도 편해진다**
   편집 모드와 제자리 저장 · 목차와 스크롤 연동 · 문서 안 찾기 ·
   상대경로 이미지와 내부 링크 · Mermaid · KaTeX · 읽기 설정 고도화 · 변경 감지
   *완료 기준 — 고친 내용이 안전하게 제자리에 저장된다*

3. **M3 — 폴더 안 거의 모든 파일을 연다**
   TOML · INI · CSV 표 뷰 · 소스 코드 · 이미지 · 폴더 전체 검색 · JSON 가상 스크롤
   *완료 기준 — 실제 프로젝트 폴더에서 "못 여는 파일"을 만나지 않는다*

4. **M4 — 도구처럼 자리 잡는다**
   PWA 설치 · 스냅샷 폴백 다듬기 · 접근성 점검 · 인쇄 스타일 · Tier 2 포맷
   *완료 기준 — 설치해 두고 매일 쓰게 된다*

## 11. 알고 시작하는 위험

| 위험 | 대응 |
| --- | --- |
| Chromium 전용 API | 폴백을 부록이 아니라 하나의 모드로 설계한다 |
| `file://`로 열면 안 됨 | README와 첫 화면에서 로컬 서버·배포 URL을 기본 사용법으로 제시한다 |
| 대용량 파일 메모리 압박 | 읽기 상한, 가상 스크롤, 워커 파싱 |
| 편집 중 실수로 덮어씀 | 기본은 읽기 모드. `⌘S` 명시 동작으로만 저장하고, 직전에 수정 시각을 재확인한다 |
| 악성 마크다운의 스크립트 삽입 | DOMPurify로 살균한다. 로컬 파일이라고 신뢰하지 않는다 |
| 번들이 계속 무거워짐 | 지연 로드 + 초기 예산 확인 |
| 포맷 욕심으로 인한 범위 확산 | Tier 0 + YAML의 완성도가 기준에 닿기 전에는 늘리지 않는다 |

## 12. 확정된 결정

1. **편집·저장을 지원한다** — 폴더 권한을 `readwrite`로 요청하되, 기본 상태는 언제나 읽기 모드.
   `⌘E`로 켜고 `⌘S`로만 저장한다. 저장 직전 디스크 수정 시각을 재확인해 충돌을 먼저 보여준다.
2. **MVP는 Tier 0 + YAML** — CSV·TOML·소스코드·이미지는 M3으로 남긴다.
3. **PWA는 M4로 미룬다** — 다만 "문서를 연다"는 동작을 진입점 하나로 모아 두어,
   `launchQueue`로 파일 핸들이 들어오는 경로를 나중에 그대로 꽂을 수 있게 설계한다.
