# 폴더째 읽는 뷰어 — 기획

> 기획안 v0.5 · 백엔드 0 · 정적 웹 · 읽기 전용 · Vite SPA · features 구조

로컬에 흩어진 마크다운·JSON·YAML·텍스트를, 업로드 없이 폴더 단위로 열어 오가며 읽는다.

| | |
| --- | --- |
| **한 번 열면 끝** | 폴더 하나를 승인하면 그 안의 모든 문서를 클릭 한 번으로 오간다 |
| **기기 밖으로 안 나감** | 업로드도 서버도 없다. 브라우저가 디스크에서 직접 읽기만 한다 |
| **오래 읽어도 편하게** | 한국어를 포함해 어떤 언어의 문서든 깨지지 않고 읽히도록 |

---

## 1. 지금은 왜 불편한가

로컬에 `.md`·`.json` 파일이 쌓이는 상황은 흔하다. 레포의 `docs/`, API 응답 덤프,
LLM이 뱉어낸 리포트 묶음, 내려받은 데이터. 그런데 이걸 그냥 *읽기만* 하려는 순간
선택지가 전부 어긋난다.

- **에디터를 켠다** — VS Code를 띄우고, 미리보기 패널을 열고, JSON은 포매터를 돌린다. 읽기 하나에 과한 절차다.
- **브라우저로 연다** — 마크다운은 원문 그대로 나오고, JSON은 한 줄로 뭉개진다. 폴더 안 다른 문서로 넘어가려면 주소를 다시 친다.
- **온라인 뷰어에 붙여넣는다** — 사내 문서나 개인 데이터를 남의 서버에 올리는 일이 된다. 한 번에 한 파일뿐이다.

빠진 것은 렌더링 품질이 아니라 **탐색**이다. 문서는 대개 혼자 오지 않고 폴더로 온다.

## 2. 누가, 어떤 순간에

| 사용자 | 순간 | 성공의 모습 |
| --- | --- | --- |
| 개발자 | 처음 보는 레포의 `docs/`를 훑는다 | 폴더 열고 30초 안에 문서 구조가 파악된다 |
| API 작업자 | 응답 덤프 `.json` 수십 개를 비교한다 | 트리로 접었다 펴며 키 경로를 바로 복사한다 |
| AI 사용자 | 에이전트가 만든 리포트 묶음을 검토한다 | 목차 따라 읽고, 문서 간 링크를 눌러 이동한다 |
| 기획·데이터 | 받은 데이터 파일이 뭔지 확인한다 | 업로드 없이 열어 훑고, 필요한 값만 집어낸다 |

넷 모두 **쓰기가 아니라 읽기**이고, **한 파일이 아니라 폴더**다.

## 3. 다른 앱과 뭐가 다른가

파일을 읽는 도구는 이미 많다. 그래서 "더 좋은 마크다운 렌더러"로는 자리가 없다.

> **에디터를 켤 만큼은 아닌데, 온라인 뷰어에 올릴 수는 없는 파일들 — 그 구간이 우리 자리다.**

| | 폴더 단위 | 포맷 한 곳에 | 업로드 없음 | 설치 없음 |
| --- | :---: | :---: | :---: | :---: |
| VS Code · Obsidian | ○ | △ | ○ | ✕ |
| 온라인 뷰어 | ✕ | ✕ | ✕ | ○ |
| 브라우저 확장 | ✕ | ✕ | ○ | ✕ |
| MkDocs · Docsify | ○ | ✕ | ○ | ✕ |
| CLI (glow · jq) | △ | ✕ | ○ | ✕ |
| **이 제품** | ○ | ○ | ○ | ○ |

### 차별점 셋

**01. 단위가 파일이 아니라 폴더다.**
경쟁 도구는 거의 전부 *한 파일*이 단위다. 온라인 뷰어는 붙여넣기 하나, 확장은 탭 하나,
CLI는 인자 하나. 폴더를 알고 있어야만 되는 일이 있다 — `[가이드](./docs/guide.md)` 링크를
눌렀을 때 *실제로 그 문서로 이동하는 것*, 문서 사이를 앞뒤로 오가는 것, 폴더 전체를 한 번에
검색하는 것. 기능을 더 넣어서 되는 게 아니라 단위를 바꿔야 되는 일이다.

**02. 포맷마다 도구를 갈아타지 않는다.**
같은 폴더 안에서 `README.md` → `config.yaml` → `users.json`을 옮겨 다니는데 지금은 도구가
셋이다. 마크다운 확장, JSON 포매터, 그리고 YAML은 결국 에디터. 하나의 트리, 하나의 검색,
하나의 읽기 설정으로 묶는다.

**03. 업로드가 없다는 게 기능이다.**
사내 문서, 고객 데이터, 운영 로그를 온라인 뷰어에 붙여넣을 수 없어서 결국 에디터를 켜게 된다.
서버가 없다는 건 "덜 만들었다"가 아니라 **쓸 수 있는 상황이 넓다**는 뜻이다.
이번 버전에서 `read` 권한만 요청하는 것도 같은 맥락 — 덮어쓸 수 없다는 것이 약속이 아니라
구조가 된다.

### 가까운 도구들과 구체적으로

- **VS Code** — 마크다운 미리보기와 JSON 포매팅을 이미 갖고 있다. 하지만 읽기 하나를 위해 켜기엔 무겁고, 미리보기는 편집 화면에 딸린 패널이지 읽기 화면이 아니다.
- **Obsidian** — 폴더(vault) 단위라는 점은 가장 가깝다. 다만 연 폴더에 `.obsidian/` 설정 디렉토리를 만든다. 남의 레포를 잠깐 훑어보려고 열었는데 흔적이 남는다. 우리는 아무것도 쓰지 않는다.
- **브라우저 마크다운·JSON 확장** — 로컬 파일을 보려면 "파일 URL 접근 허용" 토글을 켜야 하고, 그래도 한 번에 한 파일이다. 포맷마다 확장을 따로 깔아야 한다.
- **MkDocs · Docusaurus · Docsify** — 설정 파일과 빌드(또는 서빙 준비)가 필요하다. 내 프로젝트를 문서 사이트로 만드는 도구지, 임의의 폴더를 지금 읽는 도구가 아니다.
- **glow · bat · jq · fx** — 빠르지만 터미널 사용자에 한정되고, 표·이미지·문서 간 이동에서 한계가 분명하다.

### 차별점이 *아닌* 것

- **마크다운 렌더 품질** — 이미 다들 잘한다. 여기서 이기려 하지 않고, 못하지만 않으면 된다.
- **편집** — 에디터를 이길 수 없다. 그래서 이번 버전에서 뺐다.
- **오프라인 동작** — 로컬 도구는 대부분 이미 오프라인이다. 자랑거리가 아니다.

## 4. 정적 웹으로 간다

"웹이냐 크롬 확장이냐"가 첫 갈림길이었다. 결론은 **정적 웹**이다.
확장이 로컬 폴더를 더 잘 읽어줄 거라는 기대가 사실이 아니기 때문이다.

| | 정적 웹 | 크롬 확장 |
| --- | --- | --- |
| 폴더 통째 탐색 | 가능 — `showDirectoryPicker()` | 같은 API를 써야 함. 더 나은 점 없음 |
| `file://` 디렉토리 나열 | 불가 | 사실상 불가 — 크롬의 목록 HTML을 파싱해야 하고, 사용자가 권한 토글까지 켜야 한다 |
| 설치 | 불필요, URL만 | 스토어 심사 · 설치 필요 |
| 배포·업데이트 | 푸시하면 끝 | 심사 대기 |
| Firefox · Safari | 폴백 동작 | 별도 확장을 새로 만들어야 함 |
| OS에서 파일 더블클릭 | PWA 설치 시 가능 | 불가 |

**전제 조건** — 보안 컨텍스트(HTTPS 또는 `localhost`)에서만 동작한다.
`index.html`을 더블클릭해 `file://`로 여는 방식으로는 안 된다.

**한계와 폴백** — Chromium 계열 전용이다. Firefox와 Safari에는 `<input webkitdirectory>`와
폴더 드래그앤드롭으로 **스냅샷 모드**를 제공한다. 읽기는 똑같이 되지만 파일 변경 자동 감지와
재방문 복원이 없다. 배지로 명시한다.

권한은 `read`만 요청한다. 쓰기를 안 하니 승인 문구가 가볍고, 실수로 덮어쓸 경로가 구조적으로 없다.

## 5. 무엇을 열 수 있나

### Tier 0 — 제품의 정체성 (M1–M2)

`.md` `.markdown` `.mdx` `.json` `.jsonc` `.jsonl` `.ndjson` `.yaml` `.yml` `.txt` `.log`

- **마크다운** — GFM 표·체크박스·각주, 코드 하이라이트, Mermaid, KaTeX, 상대경로 이미지, 문서 간 링크 이동
- **JSON** — 접이식 트리, 키/값 검색(접힌 노드까지 찾아 자동 전개), 경로 복사, 원문/트리 전환, 주석·후행 쉼표 관용 파싱
- **YAML** — JSON과 같은 트리 뷰
- **JSONL** — 줄 단위 레코드, 깨진 줄은 표시하되 나머지는 정상 렌더
- **텍스트·로그** — 줄 번호, 줄바꿈 토글, 긴 파일 점진 로드
- **못 여는 파일도 목록에는 나온다** — 열지는 못해도 있다는 사실은 숨기지 않는다 ([7. 무엇을 보여줄지 고른다](#무엇을-보여줄지-고른다))

### Tier 1 — 같은 폴더에 늘 함께 있는 것 (M3)

`.csv` `.tsv` `.toml` `.ini` `.env` `.xml` 소스 코드 이미지

이미지가 필요한 진짜 이유는 **마크다운 안의 상대경로 이미지**다. 없으면 문서에 구멍이 뚫린다.

### Tier 2 — 있으면 좋은 것 (M4 이후)

`.ipynb` `.pdf` `.html` `.svg` `.parquet` — 전부 지연 로드.

### 범위 밖

**편집과 저장**, 파일 변환, 압축 해제, DB 파일.
이번 버전은 읽기 도구로서의 완성도에만 집중한다. 편집 설계는 [15. 추후 고려 사항](#15-추후-고려-사항)에 남겨 두었다.

## 6. 화면은 세 칸

```
┌─────────────────────────────────────────────────────────┐
│ ☰  my-project / docs / guide.md      ⌘K   Aa   ◐        │
├──────────────┬──────────────────────────┬───────────────┤
│ 파일          │                          │ 목차           │
│ 🔍 거르기      │      본문                 │ 시작하기        │
│ ▾ docs       │                          │   설치         │
│   guide.md   │                          │   설정         │
│ ▾ data       │                          │ API           │
│   users.json │                          │   인증         │
└──────────────┴──────────────────────────┴───────────────┘
```

좁은 화면에서는 트리가 서랍으로, 목차는 상단 드롭다운으로 접힌다.
아무 폴더도 열지 않은 상태가 사실상 랜딩 페이지다 — 드롭 영역, 폴더 열기,
최근 연 폴더, 그리고 "파일은 이 브라우저를 벗어나지 않습니다" 한 줄.

## 7. 읽는 동안의 손놀림

목표는 세 가지 수치다. 폴더 열고 첫 문서까지 **2클릭**, 다른 문서로 전환 **1동작**,
재방문 후 복귀 **1클릭**.

### 탐색
- **빠른 찾기** — 파일명과 경로를 함께 퍼지 매칭
- **문서 안 링크** — 상대경로 마크다운 링크는 앱 안 이동, 외부 링크만 새 탭
- **앞으로·뒤로** — 문서 이동 기록
- **이어 읽기** — 파일마다 스크롤 위치 기억

### 무엇을 보여줄지 고른다

읽기 도구의 신뢰는 **본 것이 전부라는 확신**에서 온다. 그래서 지원하지 않는 확장자를 목록에서
지워 버리면 안 된다. 폴더가 실제보다 비어 보이고, "여기 스크린샷 있었는데?" 하는 순간
도구를 의심하게 된다.

- **스캔은 전부, 표시는 골라서** — 폴더를 열 때는 모든 파일을 목록에 담고, 무엇을 보여줄지는 볼 때 정한다. 필터를 바꿀 때마다 폴더를 다시 읽지 않는다.
- **못 여는 파일도 보인다** — 흐리게 표시하고, 누르면 이름·크기·수정 시각과 "이 형식은 아직 못 엽니다"를 알려준다. 없는 척하지 않는다.
- **형식 칩** — 사이드바 위에 *이 폴더에 실제로 있는* 형식만 칩으로 뜬다(`MD 12` `JSON 5` `YAML 2` `기타 8`). 눌러서 켜고 끈다. 폴더에 없는 형식은 칩도 안 뜨므로, 칩 줄 자체가 "이 폴더에 뭐가 들었나"의 요약이 된다.
- **필터는 하나다** — 트리 · `⌘K` 빠른 찾기 · 폴더 전체 검색이 같은 집합을 본다. 트리에 없는 파일이 검색 결과에서 튀어나오지 않는다.
- **폴더마다 기억한다** — 이 폴더에서 마지막으로 고른 형식을 다음에 열 때 그대로 복원한다.
- **빈 화면을 구분한다** — "이 폴더에 문서가 없습니다"와 "필터 때문에 12개가 숨겨져 있습니다 · 전부 보기"는 다른 말이다.

지금의 `문서만 / 모든 파일` 2단 토글은 없앤다. 거기엔 서로 다른 질문 셋이 섞여 있었다 —
지원 포맷만? 텍스트도? 숨김 파일도? 앞의 둘은 칩으로, 숨김 파일은 별도 토글로 나눈다.

> **스캔 범위는 필터와 다른 문제다.** `node_modules`·`.git` 같은 디렉토리 제외는 그대로 둔다.
> 그건 "숨기는" 게 아니라 *애초에 읽을 이유가 없는* 범위다. 다만 무엇을 건너뛰었는지 첫 화면에서
> 볼 수 있게 하고, 미지원 파일은 이름·크기만 담고 내용은 읽지 않아 목록이 커져도 메모리를 쓰지 않는다.

### 검색
- **문서 안 찾기** — JSON은 *접힌 노드까지 뒤져서 자동으로 펼친다*
- **폴더 전체 검색** — 웹 워커로 모든 파일 내용을 훑는다. 이 기능이 "뷰어"를 "문서함"으로 만든다

### 단축키

| 키 | 동작 |
| --- | --- |
| `⌘K` | 파일 빠른 찾기 |
| `⌘F` | 문서 안에서 찾기 |
| `⌘⇧F` | 폴더 전체 내용 검색 |
| `↑` `↓` | 트리에서 파일 이동 |
| `⌥←` `⌥→` | 이전 · 다음 문서 |
| `⌘B` | 사이드바 접기 · 펴기 |
| `⌘+` `⌘−` | 글자 크기 |
| `R` | 현재 문서 다시 읽기 |
| `?` | 단축키 도움말 |

## 8. 어떤 언어로 쓰인 문서든

"다양한 언어"는 두 개의 다른 문제다. 섞으면 둘 다 어설퍼진다.

**UI 언어** — `navigator.language`로 자동 선택하고 수동 전환. 한국어·영어로 시작한다.

**문서 언어** — 이쪽이 진짜 난이도다. 내가 만든 문서가 아니므로 무엇이 들어올지 모른다.

- **인코딩 추론** — BOM을 먼저 보고, UTF-8 엄격 디코딩을 시도한 뒤, 실패하면 CP949·Shift_JIS·GB18030·Big5를 돌려가며 *가장 덜 깨지는* 결과를 고른다. 결과는 상태 표시줄에 밝힌다
- **줄바꿈** — 한국어는 `word-break: keep-all`로 어절 단위로 끊어야 읽힌다. 긴 URL·코드는 따로 처리한다
- **글꼴 폴백** — 문서 언어를 추정해 `lang` 속성을 붙이고 언어별 폴백 스택을 태운다. 네트워크 없이 동작해야 하므로 시스템 글꼴 기반
- **RTL** — 아랍어·히브리어가 감지되면 `dir="rtl"`
- **숫자·날짜** — `Intl`로 현지 형식

## 11. 디렉토리 구조

포맷을 계속 늘려갈 제품이다(Tier 1 · Tier 2). 그래서 구조의 판단 기준은 하나다 —
**"포맷 하나를 더 지원한다"가 얼마나 싼가.**

```
zzaim-frontend/
├── index.html
├── vite.config.ts          # base 는 BASE_PATH 로 덮어쓴다
├── docs/PLAN.md
├── examples/sample/        # 한국어·일본어·스페인어가 섞인 시험용 폴더
└── src/
    ├── main.tsx
    ├── app/                # 셸 · 레이아웃 · 전역 단축키 · 문서 디스패치
    │   ├── App.tsx
    │   ├── ui/{Toolbar,ShortcutsDialog}.tsx
    │   └── model/ui.ts     # 패널 열림 같은 전역 UI 상태
    ├── features/           # 기능 단위. 서로 직접 import 하지 않는다
    │   ├── workspace/      # 폴더 열기 · 스캔 · 트리 · 최근 폴더
    │   │   ├── ui/{Welcome,Sidebar,FileTree,RecentList}.tsx
    │   │   ├── model/{store,scan,persist}.ts
    │   │   └── index.ts    # 이 폴더의 공개 API
    │   ├── viewer-markdown/
    │   │   ├── ui/MarkdownView.tsx
    │   │   └── lib/{render,slug,links}.ts
    │   ├── viewer-data/    # json · jsonc · jsonl · yaml 공용
    │   │   ├── ui/{DataView,TreeNode,RawBlock}.tsx
    │   │   └── lib/{parse,search,path}.ts
    │   ├── viewer-text/
    │   ├── quick-open/     # ⌘K 팔레트
    │   └── reading-settings/
    ├── entities/           # 도메인 개념. 얇게 유지한다
    │   └── document/       # FileNode · DirNode · LoadedDoc · 확장자 판별
    ├── shared/             # 어디서든 쓰지만, 위로는 절대 import 하지 않는다
    │   ├── ui/{Icon,Button,Overlay,Segmented}.tsx
    │   ├── lib/{fs,encoding,format,highlight}.ts
    │   ├── i18n/{ko,en,index,useT}.ts
    │   └── config/constants.ts
    └── styles/{tokens,base,index}.css
```

### 규칙은 셋뿐이다

1. **import 방향은 한쪽** — `app → features → entities → shared`. 거꾸로 가는 화살표는 없다.
2. **feature 끼리 직접 부르지 않는다** — 필요하면 `app`이 조립하거나, 공통분모를 `entities`·`shared`로 내린다.
3. **각 feature 는 `index.ts`만 공개한다** — 내부 파일을 밖에서 직접 import 하지 않는다.

경로는 `@/` 별칭으로 `src/`를 가리킨다(`vite.config.ts`의 `resolve.alias` + `tsconfig`의 `paths`).
상대경로 `../../..`가 생기면 대개 규칙을 어긴 신호다.

### Tier 1 포맷을 붙일 때

CSV를 추가한다고 하면 `features/viewer-csv/`를 만들고, `entities/document`에 확장자를 등록하고,
`app`의 문서 디스패치에 분기 하나를 더한다. 기존 뷰어는 건드리지 않는다.
이게 이 구조를 고른 이유 전부다.

## 14. 확정된 결정

충돌하는 부분이 있으면 이 절이 앞선 내용보다 우선한다.

1. **이번 버전은 읽기 전용이다.** 폴더 권한을 `read`로만 요청한다. 파일을 고칠 수 없다는 것이
   이 버전의 *보장*이다. 편집은 읽기 도구로서의 완성도가 기준에 닿은 다음에 다시 꺼낸다.
2. **MVP는 Tier 0 + YAML.** CSV·TOML·소스코드·이미지는 M3으로 남긴다.
3. **Vite SPA 를 유지하고, 구조는 features 기반으로 간다.** Next.js로 옮기지 않는다.
   서버 렌더링도 라우팅도 이 앱에는 쓸모가 없고, 정적 산출물만 나오는 쪽이 "백엔드 0"과 정확히 맞는다.
4. **PWA는 M4로 미룬다.** 다만 "문서를 연다"는 동작을 진입점 하나로 모아 두어,
   `launchQueue`로 파일 핸들이 들어오는 경로를 나중에 그대로 꽂을 수 있게 설계한다.

## 15. 추후 고려 사항

이번 버전 범위 밖이다. 버린 게 아니라 **미뤄 둔 것**이라, 설계까지 해 두고 다음 버전에서 꺼내 쓴다.

### 편집과 제자리 저장

File System Access API는 쓰기도 지원한다. 폴더를 다시 고를 필요 없이, 이미 가진 핸들에
`requestPermission({ mode: 'readwrite' })`로 권한을 *승격*하면 된다.
그래서 지금 읽기 전용으로 시작해도 나중에 길이 막히지 않는다.

꺼낼 때 그대로 쓸 설계:

- **편집은 모드다** — 기본은 언제나 읽기. `⌘E`로 켜기 전에는 어떤 키를 눌러도 파일이 바뀌지 않는다.
- **명시적 저장** — `⌘S`로만 디스크에 쓴다. 자동 저장은 없다. 저장하지 않은 변경은 파일 이름 옆에 표시하고, 다른 문서로 넘어가려 할 때 붙잡는다.
- **충돌 방지** — 저장 직전에 디스크의 수정 시각을 다시 읽는다. 내가 연 뒤에 바뀌었으면 덮어쓰지 않고 무엇이 달라졌는지 먼저 보여준다.
- **형식 검사** — JSON·YAML은 저장 전에 파싱해 본다. 깨진 채로 저장되는 일이 없게 한다.
- **에디터는 필요할 때만** — 편집 모드 진입 시점에 CodeMirror 6을 동적으로 불러온다.
- **스냅샷 모드** — 제자리 저장이 불가능하다. 내려받기로 대체하고, 편집을 켜는 시점에 알린다.

**미룬 이유.** 편집을 붙이는 순간 "덮어쓸 일이 없다"는 보장을 잃는다.
그건 이 제품의 차별점 중 하나다. 읽기가 충분히 좋아지기 전에 그 교환을 하는 건 순서가 틀렸다.

### PWA 설치와 OS 파일 연결

manifest의 `file_handlers`와 `launchQueue.setConsumer`를 쓰면 Chrome·Edge 데스크톱에서
`.md`·`.json` 더블클릭을 이 앱이 받을 수 있다. 매일 쓰는 도구가 되는 데는 이 지점이 크다. M4.

### Tier 2 포맷

`.ipynb` · `.pdf` · `.html` · `.svg` · `.parquet`. 각각 무거운 라이브러리를 끌고 오므로
수요를 보고 지연 로드로 붙인다.

### 폴더 전체 검색의 인덱싱

M3의 전체 검색은 매번 훑는 방식으로 시작한다. 폴더가 아주 커지면 IndexedDB에 역색인을 두는
쪽을 검토한다. 다만 "열 때마다 최신"이라는 성질을 잃지 않는 선에서만.
